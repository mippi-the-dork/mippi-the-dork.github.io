## Design Intent

Epic changes more than the site's color palette.

It introduces a more active layer above the normal portfolio content.

The player needs a lightweight explanation that the page now contains new airborne opportunities.

This prevents the first UFO, Shooting Star, or flying collectible from feeling like a random unrelated event.

## What the Onboarding Communicates

The Epic airspace message should establish that:

- the environment has changed,
- new things can appear,
- some airborne objects are interactive,
- the player should keep an eye on the screen rather than only the document flow.

It does not need to explain every object in advance.

The player can still discover:

- Rupees,
- Hearts,
- Stars,
- Keys,
- UFOs,
- Shooting Stars,
- Boss escalation

through play.

## Timing

Epic unlock already contains visual and progression feedback.

Airspace onboarding should not land in the exact same frame if doing so causes a wall of messages.

It should arrive after the main Epic transformation has registered.

## One-Time Nature

The onboarding should occur once per session rather than every time the player changes back to Epic visual theme.

This is important because gameplay unlock is independent of selected theme.

## Theme Separation

Airspace onboarding is tied to Epic progression.

It is not tied to currently displaying the Epic theme.

A player who unlocks Epic and immediately switches back to Rare should still retain airborne gameplay.

## Design Rules

- Introduce the concept, not every object.
- Trigger from progression, not theme choice.
- Do not repeat when cycling themes.
- Do not require the player to keep Epic selected.
- Avoid stacking on top of stronger authored moments.

## Success Criteria

The first late-game airborne event feels like the next chapter of the same experience rather than an unexplained intrusion.
